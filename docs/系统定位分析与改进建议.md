## 问题一：能不能在线编辑？

### 结论：不能。这个系统的"编辑"是编辑**文档信息**，不是编辑**文档内容**。

用类比说清楚这个区别：

| 类比 | 本系统做的 | 腾讯文档/飞书文档做的 |
| --- | --- | --- |
| 相当于 | **图书馆的图书卡片目录** | **图书馆里能直接写字的书** |
| 管理对象 | 文档的"身份证信息"（名称、类型、介绍、附件链接） | 文档的正文内容 |
| "编辑"含义 | 改名称、改类型、重新上传附件 | 在页面上打字、改字、多人协作 |
| 有没有正文 | ❌ 数据库没有正文字段 | ✅ 有正文内容存储 |

### 代码级证据（不是猜的）

1. **文档表 `wendangxinxi` 只有 7 个字段**：
   ```
   id / 文档名称 / 类型 / 文档介绍 / 附件(fujian) / 发布日期 / 创建时间
   ```
   **没有任何"正文内容"字段**——没有地方存储你在页面上打的字。

2. **后端全量搜索** `ueditor / ckeditor / tinymce / quill / wangeditor / editor / 富文本` → **零匹配**。后端没有任何富文本编辑相关的接口或依赖。

3. **老师自带的老版前端**里也没有 ueditor 等编辑器目录（只有 static/upload 存上传文件）。

4. **数据库真实数据**印证：`fujian` 字段存的是 `http://.../upload/1617346216078.pptx` 这样的**静态文件链接**，点"查阅"就是下载/打开这个 pptx，不是在网页里编辑。

### 那现在能"编辑"什么？

后台的"新增/编辑文档"能改的是：文档名称、类型、介绍、发布日期、重新上传附件。这是**元数据管理**，属于文档管理系统的正常功能，但和"在线编辑文档内容"是两码事。

> 如果老师题目里的"在线文档管理"本意就是"在线管理文档"（上传、分类、检索、下载），那现在的实现是完全对题的。如果老师期望的是"在线编辑"，那题目本身和给的代码就对不上——这个可以下节课直接问老师确认。

## 问题二：功能定位是不是不清晰？有啥改进？

### 你的直觉是对的——现状确实"定位模糊"，原因不在你，在题目本身。

题目叫"**基于 SpringBoot 的在线文档管理系统**"，"在线文档管理"有两种理解：

- **理解 A（目录式管理）**：管文档的上传、分类、检索、下载 ← **老师和代码走的是这条**
- **理解 B（协作式编辑）**：像腾讯文档那样在线写、协作 ← 题目字面容易让人这么想

老师给的代码是 2021 年的通用代码生成器模板，8 张表里混着"部门/岗位/员工"这些**企业人事管理**的表，和"文档管理"主题其实是拼凑的——这就是你觉得"定位不清晰"的根源。

### 现有功能盘点

| 模块 | 数据表 | 和"文档管理"主题的相关度 |
| --- | --- | --- |
| 文档信息 | wendangxinxi | ⭐⭐⭐ 核心 |
| 公告信息 | gonggaoxinxi | ⭐⭐ 辅助（资讯发布） |
| 部门 / 岗位 / 员工 | 3 张表 | ⭐ 弱相关（人事管理遗留，可讲成"组织架构与文档归属"） |
| 用户账号 | users | ⭐⭐ 支撑登录 |

### 改进建议（按投入从低到高，附权衡）

| 方案 | 做法 | 优点 | 成本/风险 | 建议 |
| --- | --- | --- | --- | --- |
| **A. 讲清定位（推荐先做）** | 不改代码,答辩时明确说"本系统是在线文档**管理**平台,核心是文档的分类、检索、上传下载,不是内容协作编辑" | 零成本,一句话消除歧义 | 无 | ⭐ 必做 |
| **B. 增强检索/分类体验** | 前台加文档类型标签云、按类型筛选、按日期排序、关键词高亮 | 纯前端改动,效果明显,好演示 | 低,半天 | ⭐ 推荐 |
| **C. 加富文本公告编辑器** | 公告"内容"字段是 longtext,可前端引 wangEditor/TinyMCE,后端字段能直接存,不用改库 | 能看到"在线编辑"的效果,回应题目歧义 | 中,要加依赖+调后端 | ⭐ 有余力可做 |
| **D. 真·在线文档编辑** | 引入 OnlyOffice / 文档转 HTML 编辑 | 完全对题"在线编辑" | **高,要装第三方服务/改后端,课程作业不值当** | ❌ 不建议 |
| **E. 砍掉弱相关表** | 隐藏部门/岗位/员工菜单,只留文档+公告+账号 | 主题更聚焦 | 低,但老师给的表藏了可能被认为没做完 | ⚠️ 谨慎 |

**我的推荐组合：A + B**。先把定位一句话讲清楚（这是"不清晰"的根本解法），再加一点检索分类的前端增强让演示更出彩。C 作为加分项,如果老师明确说要"在线编辑"再上。

## 问题三：下次如何启动这两个页面？

### 一句话版

先起后端,再在两个终端各跑一条 `npm run dev`。

### 详细步骤

**第 0 步：确认数据库**

MySQL 服务 `MySQLDefaults` 默认自启，一般不用管。

**第 1 步：启动后端（8080）**

二选一：

- 方式 A（推荐,符合板书）：IDEA 打开 `backend`，运行 `SpringbootSchemaApplication`
- 方式 B（命令行）：
  ```bash
  "E:/02-Dev/JDK/8/bin/java.exe" -jar "backend/target/springbootpkh49-0.0.1-SNAPSHOT.jar"
  ```
  ⚠️ 必须用 JDK8 绝对路径（系统 PATH 默认 JDK21）。看到日志 `Tomcat started on port(s): 8080` 即成功。

**第 2 步：启动两个前端**

开两个终端窗口：

```bash
cd "C:/Users/Administrator/OneDrive/Desktop/前端项目/admin"
npm run dev        # 后台 → http://localhost:5173

cd "C:/Users/Administrator/OneDrive/Desktop/前端项目/front"
npm run dev        # 前台 → http://localhost:5174
```

**第 3 步：访问**

| 页面 | 地址 | 账号 |
| --- | --- | --- |
| 后台管理 | http://localhost:5173 | abo / abo |
| 前台门户 | http://localhost:5174 | 免登录 |

### 常见启动故障排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 后端报 `Port 8080 was already in use` | 上次会话的 java 进程残留 | 任务管理器结束所有 `java.exe`,或用 `Stop-Process -Name java -Force` |
| 前端报端口被占 | Vite 设了 strictPort,不会自动顺延 | 结束占用 5173/5174 的 node 进程 |
| 页面能开但没数据 | 后端没起 / 数据库没连上 | 先确认 8080 可访问,再看后端日志 |
| npm 提示 esbuild 警告 | npm 11 的 install-scripts 策略 | 忽略,不影响运行 |
